How to read the colours

Green/orange/red on the platform drawing summarise the realization ledger for each subsystem: green = every part reaches a Configuration 1 product consistently; orange = a part with no allocated block or an unclear product role; red = a missing product realization or a realization whose Configuration 1 role names a different functional part.

Recommended model changes: realization ledger

Proposed edits to the Berserker Allocated Baseline Model and Product Baseline Library. Each follows from a flag above; none has been applied to the uploaded .mdzip files. Where the evidence cannot tell which baseline is right, both options are given.

  1. fixAdd a Realization from Curtiss-Wright Parvus DuraCOR Pi to Allocated Mission Controller in the Product Baseline Library.
    WhyAllocated Mission Controller is the only allocated block with no product realization, yet Berserker Configuration 1 already contains a part Mission controller : DuraCOR Pi. The configuration and the realization graph disagree; the thread from Mission Controller (122 allocated functions in Executive Control) currently dead-ends before any product.
  2. fixUntangle the Navigation / flight-control realizations: retarget VECTOR-600 → Allocated Flight Control Computer to Allocated Nav Sensors, retarget VectorNav VN-310 → Allocated Nav Sensors to Allocated Nav Controller, and add DuraCOR Pi → Allocated Flight Control Computer (or, if the realizations are right, rename the Configuration 1 parts Navigation Sensor, Navigation Controller and Flight Controller to match).
    WhyConfiguration 1 types its Navigation Sensor part with VECTOR-600 and its Navigation Controller part with VN-310, but the Realization relationships say VECTOR-600 realizes the flight control computer and VN-310 realizes the nav sensors, while DuraCOR Pi (the Configuration 1 Flight Controller) realizes the nav controller. One side is wrong; every navigation requirement (28 touch this subsystem) inherits the ambiguity.
  3. fixIn Configuration 1, retype the part Munitions from UAV Solutions MRAK to GBU-39/B Small Diameter Bomb and add a part Antenna : UAV Solutions MRAK.
    WhyMRAK realizes Allocated Antenna but sits in the configuration as the weapon; GBU-39/B realizes Allocated Weapons and is not in the configuration at all, so Configuration 1 carries no munition and no antenna despite the Stores Management and Communications subsystems both being modelled.
  4. fixIn the Fuel Management chain, realign Configuration 1 roles with the realizations: Fuel Sensor : Reventec LS200, Fuel Pump : Currawong CE370, Engine Controller : RCV EFI UAV Engine Control System (or move the Realization targets one slot).
    WhyThe roles are shifted by one slot along the chain — the product that realizes Fuel Sensors is the Fuel Pump part, the product that realizes Fuel Pump is the Engine Controller part, and the product that realizes Engine Controller is an Engine Interface module. A consistent shift like this is usually a copy/paste error in one of the two baselines.
  5. fixRename the Configuration 1 part Electric Controller : HYBGEN 32 to Generator, and decide which product is the electrical controller — PowerMaster Control Suite (in Configuration 1 as Power Distribution Unit) or Autonomic Power Hub APH-700 (realizes it, but absent from Configuration 1).
    WhyHYBGEN 32 realizes Allocated Generator, and Allocated Electrical Controller has two product realizations of which only one is configured, under a role name that matches neither. Electrical is the power source for every subsystem (8 power connectors), so its realization should be unambiguous.
  6. shouldComplete Configuration 1 or mark alternates: Aeroprobe Multi-Hole Air Data System, Autonomic Power Hub APH-700, Crystal Group RS260 Rugged Server, GBU-39/B Small Diameter Bomb, SmartEO/IR Pod SX-550 are realizations that appear in no configuration.
    WhyA product realization without a configuration part cannot be costed, weighed or tested against a build. Notably no Air Data Sensor product is configured although the functional model has an AirData Interface port and an Air Data Sensors part, and no EO/IR pod alternative is recorded as such.
  7. shouldFix the misspelt element names that break name-based traceability: Flight Controlller, Allocated Cyber Centinel / Configuration 1 Cyber Centinel, CharingPortAC.
    WhyCameo's own search, the STPA-Sec controller names (C-9 Flight Control Computer, C-30 Cyber Sentinel) and any script-based RVTM all match on names; these three misspellings already cost matches in this analysis.
  8. considerModel 1553 Bus, 28VDC Power, Raw Video Stream as flow/interface elements rather than parts, or give them allocated realizations.
    WhyThey are the only functional parts with no allocated counterpart. If they represent buses and flows, an InterfaceBlock / ItemFlow keeps the ledger clean; if they are equipment, they need a realization like every other part.
